# Election lifecycle backend

The shared seat context is a coherent120-seat parliament. Its separate optional uncertainty references joint draws and marginal intervals; marginal medians are never assembled into a parliament. The live model's version2 representative point selects an actual seeded joint draw minimizing absolute distance from draw means, with deterministic first-draw tie breaking. Original `data/forecast.json` and its history are not regenerated by this feature.

## Commands and release contract

- `npx vitest run lib/election-lifecycle lib/live-forecast lib/briefing.test.ts` runs focused domain/source/worker checks.
- `npx tsx scripts/election-lifecycle/probe.mts` performs bounded primary-source reads and prints availability/schema status without secrets. Run from the deployment region as well as locally. A successful fetch is not a successful event/finality extraction.
- `npx tsx scripts/election-lifecycle/schedules.mts` prints the exact schedule plan. Release owner adds `--apply` only after gates; `--pause --apply` pauses those environment-specific schedules. Existing Redis and QStash resources are reused.
- `freeze-campaign.mts` creates immutable campaign comparator data only before close and refuses overwrite. The committed capture is provisional unless a saved forecast was already marked final. No retrospective registration. Forecast script now blocks all post-close writes including `--final`; read-only sensitivity remains allowed. Intentional historical regeneration needs `--allow-historical-regeneration` and cannot make a new final submission after close.

Required Vercel flags: `ELECTION_LIFECYCLE_ENABLED=true`, `ELECTION_OFFICIAL_ENABLED=true`, `ELECTION_FORMATION_ENABLED=true`. Exact signed destination `ELECTION_LIFECYCLE_WORKER_URL=https://<environment-host>/api/election-lifecycle/worker`. Existing `KV_REST_API_URL/TOKEN` (or UPSTASH equivalents), QStash signing keys and `GEMINI_API_KEY` are reused. No credentials enter public output. Namespace `election-lifecycle:2026:v1:${VERCEL_ENV or development}:`, optionally `ELECTION_LIFECYCLE_NAMESPACE`; preview and production must differ.

The first slow slot isOctober28 06:00Z(Israel08:00), then09Z/12Z/15Z/18Z/21Z/00Z/03Z every3hours. No automatic preclose acquisition. The night QStash cron self-gates and receives a delayed signed `pause_night` at06Z; only its night-ID is paused. The regular cron continues afterNovember3 for official/formation acquisition. The model's originalNov3archive cutoff remains. Daily structured briefing reads stored lifecycle state without upstream acquisition; existing prose/history publication remains.

Signed `{mode:"cycle",window:"night"|"regular"}` invokes a bounded model/count stage, which records per-cycle raw-count receipt, publishes the model, then enqueues a separately signed `{mode:"cycle",stage:"authority",cycleAt:ISO}`. Authority reads the published model and countCSV; it alone acquires official national results and political sources, and geography reuses thatCSV. Model retries reuse successful count acquisition; queue retries reuse completed model publication. After3failed model attempts, authority may continue with explicit last-good/stale model evidence. A delayed prior-slot delivery is superseded before any acquisition; future/nonaligned cycles are rejected. All stages have environment-isolated progress/leases. No count-informed model gate is activated.

Release owner first verifies code/preview, then creates the new schedules and delayed-pause receipt using `schedules.mts --apply`, verifies exact next triggers, and pauses the old live-forecast minute plus lifecycle election/formation schedules. New IDs are `lifecycle-<env>-night-2026`, `lifecycle-<env>-regular-2026`, existingdailybriefingID. OldNov3cleanup must target only oldIDs, never the continuingregularID. The old GitHub10minuteexit andautomatic count-capture schedules are removed; campaign daily imports stop automatically afterclose, while workflow_dispatch remains available. ## Public contract

`getElectionLifecycle({revision?})`, `getSharedSeatContext({revision?})` are server getters; React request caching deduplicates reads. Missing explicit pins return unavailable/404. Current mode may auto-update seat numbers; consumer UI preserves user parties/roles and highlights changes. A shared link pins **seats only**, explicitly `selection.mode=pinned`; its political panel is labeled current and always recalculated/redacted. Never mix historic event rows with a current clock.

`GET /api/election-lifecycle` returns current visible state with `no-store`. `?view=seats` returns thin seats/alternatives/source-health/selection metadata with shared30-second caching. Both use one resolver and underlying revisions. Evaluation is `/evaluation?revision=...`; geography is `/geography?revision=...`; daily structured references are `/briefing`. Full politics/briefings are never CDN cached, including pinned reads. Internal ledger, raw captures, withheld quotations, extraction cache and correction records are not public endpoints.

Redis stores immutable captures and seat/root revisions, an internal event ledger, ordered publication sequence, source health and idempotent receipts. Publication is atomic under a120-second owner lease. Sequence may have gaps after a failed attempt; it never goes backwards. Seat snapshot metadata is fixed at its first publication; root sequence orders later public health/event changes. Existing official seats remain available with status notice during source failures; a compatible process last-good ledger survives Redis outages. A cold process without Redis cannot retrieve an uncached official record and must show explicit source failure rather than claim fresh campaign evidence; client last-good retention is required.

## Authorities, extraction and redaction

CEC official publication needs current election identity/date, an explicit final-official heading and a complete120-seat named table. Test environments and future publication notices are rejected even after close. CSV completion is not finality. Conflicting valid mirrors withhold promotion; official corrections append a new allocation/source lineage even with older source timestamps. Unknown elected lists are retained with official names and neutral identifiers.

Political registry sources are scoped to President, Knesset or verified party-owned hosts. New primary article discovery has reserved budget alongside rotating revalidation of known claim URLs. At most eight source fetches and three model extractions run concurrently/per worker respectively. Successful extraction including zero events is cached by normalized article body/publication/authority metadata rather than rotating HTML widgets. External text is untrusted data. Structured extraction is checked against exact original evidence, actor names, date, type-specific authority and action language; speculative claims and unsupported dates are rejected. Party sources can establish their own stance only; joint agreements require joint/official evidence. No video transcription or guessed feed success.

Confidence decisions are scoped to an explicit nominee/proposal. Cabinet refusal is not confidence opposition. Unknown choices stay undecided. Contradictions from the same edited page or different sources/dates are disputed, not silently overwritten. Only an evidenced explicit correction/retraction can supersede a conflicting stance; disputed recaptures cannot reactivate it. Removed source quotations are retracted internally. Unavailable, disputed or un-revalidated source claims, derived proposal decisions and clocks are omitted from public current responses. Healthy independent claims continue. Pinned reads and daily briefings reapply the same redaction; no cached historical payload revives a withheld claim.

Clock anchors use actual published events. First/second mandates are28days; final mandate14. An extension applies only to an explicit first mandate, with explicitly additional/cumulative granted durations totaling at most14. No implicit extension. If mandate stage or extension semantics are unknown, the clock is withheld. Official publication-to-assignment dates require an explicit occurred Official Gazette publication notice and date; ordinary website article publishedAt is provenance only; election day, first observation and HTTP Last-Modified do not substitute.

## Evaluation and geography

Frozen comparators include forecast v3/v2, both polling averages, source revisions and the party/bloc mapping at capture. MAE uses each prediction's declared list universe; unexpected elected lists and full-parliament error are separate. Threshold grading uses saved calls/pass probabilities, and modal majority grading is separate. Bloc party-sum and model-point errors are both retained. Every evaluation references the exact official result revision; corrected official outcomes re-score transparently without editing predictions.

Geography ingestion reuses strict CSV totals validation, retains all ballot letters, separates special envelopes and replaces complete snapshots so corrected counts may decrease. Unknown locality/party data is not invented. Coverage stays unknown until all published official party vote totals reconcile exactly to locality+envelope totals. Only then can the2026 adapter become a completed historical vote map. This does not activate the independent count-informed forecasting gate or infer alliance vote transfers.

## Emergency captured primary evidence

`npx tsx scripts/election-lifecycle/import-evidence.mts --file capture.json --url https://<verified-primary-host>/exact/article --target preview` is a read-only dry run. The capture must be original HTML with a matching canonical URL, or an envelope `{ "sourceUrl": "exact original URL", "html": "original captured HTML" }`. Verified registry hosts, current election identity, after-close gate, test-environment rejection and ordinary strict extraction/finality checks still apply. This is not an arbitrary seat/event editing route. PDF/image-only evidence needs a verified parser first. `--apply --operator <audit-identity>` publishes atomically with private provenance audit. Production additionally requires `--target production --confirm-production`; use environment-matching credentials and namespace. No raw captures or operator identity enter public responses.

The signed worker body `{ "mode": "probe" }` performs the deployment-region read-only diagnostics without flags, Redis writes, model extraction or factual publication. HTTP success is not parser acceptance. Enabled but missing durable credentials, and a cold durable-store outage, return explicit503; flag-disabled local previews retain the qualified campaign baseline.

Primary DOM validation follow-up: the adapter supports actual nested Elementor single-post bodies and individually dated Democrats JetEngine excerpts. Each excerpt keeps its own post-id fragment/date; homepage/site creation metadata never dates all excerpts. Recorded selected primary DOM elements are fixture evidence, with old campaign content still rejected as current negotiation facts. Yashar currently exposes platform text/video links rather than a supported dated article feed; this is source coverage, not a claim that its homepage is blocked. Allowlisted ordinary HTTPS canonical redirects are followed up to3hops with one8second budget; cross-host unverified, maintenance/geo/challenge and no-Location redirects are rejected without bypass. Probes include redirect/error status, resolvedURL and dated-excerpt/body/date metrics; empty200 is unavailable.

The signed no-write body `{ "mode": "extraction_probe" }` runs the same extractor against one fixed real primary article and returns only configured/model/stage/provider HTTP+status category/accepted-count. It publishes no facts or captures. Provider errors remain distinct machine diagnostics (for example `provider_billing`,402,`RESOURCE_EXHAUSTED`); raw error messages, source text and keys are never returned. The2026-10-26deployed probe confirmed that402externalbilling failure. It needs a provider account/quota decision, not fabricated claims or a silent model/key switch. Missing credentials are a failed acquisition, not a cached successful zero-event capture. Successful zero-event extraction remains valid; failed extraction remains retryable.
