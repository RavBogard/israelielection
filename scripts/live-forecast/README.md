# Live Balance of Power backend

This experimental layer is separate from the scored pre-election forecast. `data/forecast.json` is untouched. `data/live-forecast-prior.json` freezes that forecast and its polls, calibration, party/bloc mapping and agreements with SHA-256 hashes. The recorded source forecast was **not final** (`final:false`, generated October25); this snapshot does not falsely certify it as a final submission. A different final prior requires an explicit new versioned file and model revision.

Run `npx tsx scripts/live-forecast/generate.mts` to reproduce the compact committed baseline. Run `npx vitest run lib/live-forecast` for joint-model, source, authentication, durable worker state and geographic guards. Run `npx tsx scripts/live-forecast/replay.mts` for all five archived elections under synthetic small-first and large-first reporting orders. This uses actual final locality counts with synthetic order, oracle national priors, named lists and arbitrary alternating blocs. It tests plumbing and120-seat invariants, **not** forecast calibration, genuine count timing, or historical predictive accuracy. `freeze-prior.mjs` refuses to overwrite an existing prior.

`GET /api/live-forecast` is cached at the shared edge for30seconds. It reads durable Redis only, never scrapes or simulates on viewer visits. `getLiveForecast()` supplies the same last-known-good snapshot to server rendering. Feature flag `LIVE_FORECAST_ENABLED=true` enables reads/worker; false returns the reproducible baseline. Missing credentials return baseline. Redis read errors explicitly mark the fallback stale. Freshness follows the shared due slot plus five minutes of grace (15minutes on electionnight,3hours thereafter), rather than five minutes after every check; successful checks of unchanged valid source data refresh acquisition health without changing the model generation timestamp or history.

`POST /api/live-forecast/worker` accepts only QStash HS256 signed requests bound to `LIVE_FORECAST_WORKER_URL`, issuer, validity window and SHA-256 raw-body digest; both rotation keys are supported. The former one-minute schedule is superseded at release by the coordinated lifecycle cadence:quarter-hourly electionnight, then3hourly. Keep this direct signed route for explicit manual recovery only; destination must exactly match the environment URL. See `scripts/election-lifecycle/README.md`. The worker is bounded to October26 through November2UTC, with exit/count ingestion blocked before October27 20:00UTC. Delete/pause the schedule after the window. Signed duplicate delivery receipts,90-second ownership lock, immutable input revisions and atomic Redis Lua publication protect retries and partial failures. A lock loser returns503 for retry. Distinct snapshots are retained in durable history (maximum1440); public trace retains240 actual model changes. Unchanged refreshes do not append history.

Credentials: `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` (or Vercel `KV_REST_API_URL` / `KV_REST_API_TOKEN`), `QSTASH_CURRENT_SIGNING_KEY`, `QSTASH_NEXT_SIGNING_KEY`. `QSTASH_TOKEN` is for provisioning schedules, never required in the request. Redis namespace is `live-forecast:2026:v1:${VERCEL_ENV or development}:`, optionally overridden by `LIVE_FORECAST_NAMESPACE`. Preview and production must use distinct namespace values and exact worker destination URLs. Revisions include frozen prior/input hashes, model and scenario versions and canonical publisher estimates. Incompatible stored versions are refused. There is no production fixture override, upload endpoint, or body-driven source selection.

Sources are checked independently. Channel13's real captured `__NEXT_DATA__.props.pageProps.page.Content.Item.timeLines.*.elements` schema is supported. Each timestamped element must explicitly identify an exit poll and contain one isolated complete120-seat paragraph with unique known party names; partial corrections are not combined across paragraphs. Broadcaster index discovery restricts URLs to configured broadcaster HTTPS hosts; `LIVE_CHANNEL13_SOURCE_URL`, `LIVE_N12_SOURCE_URL`, `LIVE_KAN_SOURCE_URL` can select a current article. Actual2022 Channel13 fragments demonstrate why validation matters: the original complete-looking list sums121, and a later correction duplicates a party. Those fragments are rejection fixtures, not evidence of a successful2026 adapter. N12's inspected2022 page embeds a separate story widget; Kan often returns403. Neither has a verified complete estimate parser, and health reports that limitation. No OCR, guessed numbers, unverified generic JSON endpoint or direct-source success is claimed. Complete N12/Kan adapters remain a launch limitation. Validated Wikipedia wikitext uses the existing pure importer; it never runs the poll mutation job. Publisher mirrors are deduplicated; Channel14 and i24NEWS stay excluded. Publication/broadcast time and observed time are distinct; page revision time is never relabeled broadcaster publication time.

Every figure uses the same joint seat draws. Largest-party and Netanyahu-versus-core-opposition categories include an explicit tie and sum to100%. Categorical probabilities are empirical frequencies; presentation uses less-than/greater-than display caps instead of claiming certainty. Scenario success uses cabinet plus outside support **yes > opposition no**, with abstentions excluded, as in the existing arrangement helper. Arrangements can overlap and are not normalized alternatives. Margins are computed per draw, never by subtracting marginal medians. Seat/margin intervals are10th–90th percentiles (80%). Bernoulli scenario/threshold estimates use Jeffreys half-count smoothing; Monte Carlo errors concern simulation precision, not predictive calibration.

Exit estimates retain the campaign model's broad shared Student-t bloc errors, sector noise and list errors; campaign mean lean/list priors/sector mean shifts are disabled. This is deliberately conservative and is **not a historically fitted exit-poll likelihood**. Multiple publishers are averaged with shared correlated uncertainty; their probabilities are never multiplied. Threshold impact is scenario success conditional on the party passing minus success conditional on failing, an association, not a causal counterfactual. Both groups need at least200draws. Ranking is four times pass-probability variance times maximum absolute scenario difference. Split-half simulation stability gates publication. Scenarios and builder pledge warnings remain separate from hypothetical arithmetic.

The CEC count adapter validates and retains locality structure rather than interpreting reporting localities' eligible voters as percentage counted. Double envelopes are separate. Its successful fetch is currently recorded as **rejected for model ingestion**: the2026 feed does not yet have verified counted/total-station coverage or completed-locality flags. This is the concrete count gate. Geographic research code requires that metadata explicitly, re-runs from the complete corrected snapshot (decreases allowed), uses continuing-party profiles and pooled profiles for new/split lists, reconciles the national prior, and carries turnout plus shared bloc and locality uncertainty. Synthetic replay cannot establish2026 source semantics. To activate count-informed publication, first capture real2026 CSV revisions and documented coverage fields, add an adapter mapping to those fields, verify partial/corrected/special-envelope examples, validate calibration against historical/replayed data, and review uncertainty contraction. Until then odds remain prior/exit-informed even when the separate results page shows counted votes; official source health says why.

QStash verification follows [Upstash's manual signature contract](https://upstash.com/docs/qstash/howto/signature). Direct schema evidence: [Channel13 2022 timeline](https://13tv.co.il/item/news/politics/politics/elections-2022-903309767/), [N12 2022 embedded page](https://www.mako.co.il/news-israel-elections/election_2022/Article-a1ad37744343481027.htm).

A successfully rechecked direct publisher estimate takes priority over the same publisher mirrored on Wikipedia, including equal timestamps and later Wikipedia observation times. When direct acquisition fails, the latest validated fallback/retained estimate is used. The pure importer records revised Wikipedia estimates by first-observed time for ordering; that internal ordering field is not asserted as broadcaster publication time. Public Wikipedia source `publishedAt` stays null, while `observedAt` and acquisition health record the successful check. Per-publisher selection is deterministic and mirrors never multiply publisher weight. Hebrew full/short names are loaded from the established translation dictionary for every known list, including minor lists. Channel13 timezone-aware timestamps keep their supplied offset; naive timestamps use the configured election offset.
