# Political record foundation

This foundation leaves Redis and the deployed lifecycle pipeline authoritative. No application request applies SQL, backfills data, creates services, or promotes Postgres. Current forecast artifacts, schedules and shared pins keep their existing semantics; count-informed odds remain validation gated.

## Callable interfaces

- `registry.ts`: stable parliamentary-term election IDs; the configured 2026 election is `il-knesset-26`. New election definitions still require evidence-backed workspace gates (qualified source configuration, archive routing, date, namespace and seven locales). The current-only acquisition adapters are not automatically qualified for another election.
- `records.ts` / `types.ts`: immutable revision envelopes for entities, proposals, mandate attempts, events, claims, publications, language editions, parliamentary membership, bills and roll calls. Publication/outbox creation is atomic. Outbox intents contain no subscriber addresses; subscription delivery is a separate private boundary behind capability flags.
- `identity.ts`: person aliases require evidence; proposal identity uses a source-issued ID or immutable initiating event, independently of later corroboration. Mandate linkage requires an explicit verified assignment mapping. Legacy person-scoped targets remain unresolved until mapped; no guessed attempt numbers.
- `PostgresPoliticalRecords`: parameterized append transactions, content-addressed source/capture identities, immutable SQL triggers, revision lookup, latest-per-record projection and monotonic `changes(after)` cursor. Append transactions serialize cursor assignment/commit with an advisory lock. `listRevisions` is lexical revision pagination for frozen exports, **not** an incremental change cursor. Latest queries expose an as-of high-water mark and truncation; withdrawn/corrected revisions remain in history.
- `CaptureArchive`: immutable private bytes, separately referenced from public records. `LocalCaptureArchive` is a nonproduction rehearsal adapter with byte-hash checks and path restrictions. Production private object storage and restricted database roles remain unconfigured and require review.
- `lifecycleBatch` / `shadowLifecycle`: deterministic backfill and comparison without promoting the new store. Exact historical SourceRef metadata binds provenance to the original capture, never a later same-URL revision. Missing bytes remain `missingCapture`; mixed/unregistered legacy elections are rejected. Legacy evidence remains `legacy_import` rather than being upgraded to newly confirmed facts.
- `getPoliticalPlatformReadModel`: request-cached server bridge to live lifecycle plus optional durable reference records. `POLITICAL_RECORD_READ_ENABLED=true` enables configured DB reads; unset remains off. Storage failures stay explicit without replacing lifecycle evidence. The legacy record window remains reference-only; the separate typed `global` projection qualifies CBS, documented-schema parliament records and commitment evidence without inferring membership from seats. `recordWindow` reports as-of/truncation; current records use latest insertion order, including backdated corrections.

## Private readiness and current-election coverage

The existing signed worker accepts `{ "mode": "readiness" }`. It performs stored-state diagnostics only and returns source/party coverage counts, provider-independent overdue/incomplete states, archive/database configuration and the count-model gate. No raw evidence, credentials or signature is returned. Keep request signatures private.

Acquisition deduplicates URLs, checks up to 12 existing articles per configured source in cadence-deadline order, then reserves three discovery candidates. HTML is reused within a cycle for fragments on the same allowlisted page; actual quote revalidation is independent of the three-extraction budget. Pending extraction is persisted internally. This is a bounded recovery policy, **not** a full revalidation SLA for arbitrarily large claim sets: unchecked claims expire using the existing cadence deadline and are withheld; private capability diagnostics block incomplete/overdue coverage. Discovery/index failures do not stop independently reachable known articles. Zero-article sources distinguish unchecked, unavailable and successfully checked with no qualified fact. Missing party feeds remain unconfigured, not opposition.

## Rehearsal commands

`npx tsx scripts/election-lifecycle/political-record.ts schema` reports a dry-run migration summary. `backfill --ledger=<private-ledger-file>` validates and summarizes without writes. Explicit `--apply --target=development|preview` requires `POLITICAL_RECORD_DATABASE_URL`; `schema` then applies the reviewed DDL, and `backfill` or `compare` writes/imports or compares records. Optional `--archive=<private-directory>` archives captured public-source bytes only on an explicit nonproduction apply. Never place the ledger or archive under public/ or commit it. The CLI refuses a production target/environment and never prints a connection string or source assertions. No production migrations have been run.

`npx vitest run lib/political-record lib/election-lifecycle/readiness.test.ts lib/election-lifecycle/sources.test.ts` exercises the exact DDL in PGlite (real PostgreSQL WASM), triggers, rollback, idempotence, correction selection, cursors, capture binding and acquisition bounds. PGlite's single session substitutes only the advisory-lock call; this does not prove production concurrency, credentials, least-privilege roles, backup/restore or service durability. Those remain cutover gates. No Postgres/Blob/email services are configured or purchased.

Additional implemented paths remain behind default-off flags: source-driven formation completion/failure, strict stored CBS observations, private Blob captures, versioned read-only API and isolated consent/outbox delivery. See [RUNBOOK.md](RUNBOOK.md) for exact interfaces, configuration, rehearsal commands and remaining activation gates. New legal clocks remain unqualified pending current authoritative law access.


Operations now include fixed-public three-country HTTP/TLS checks, independent seven-edition rendered smoke, categorical stored-source diagnostics and private incident deduplication/recovery history. Their new workflow schedule remains off by default. No service was provisioned, no production database migration ran, and no messages were sent. The next integration boundary is the actual stored-briefing/authoritative-change automatic publication producer; a private reviewed-edition CLI is not presented as a complete automatic publishing pipeline.
