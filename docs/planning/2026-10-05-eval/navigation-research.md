# Navigation research — 2026-10-05

Research completed; root authorized bounded implementation after this handoff. User asks for thoughtful top navigation and better awareness of all resources. Root direction: five disclosure categories, visible Start here / All resources / Search, responsive inline mobile expansion, and a server-rendered resource directory. Audience balance remains new readers and educators pending a user preference. Political worker inventories routes separately.

## Recommendation and evidence

Keep the paper/ink masthead and sparse homepage. Replace the twelve-link horizontal strip with five plainly named category buttons: Parties & coalitions, Polls & updates, Election explained, Teaching resources, About & contact. Each opens one bounded, flat panel of named links with short descriptions. Add a visible `/resources` directory link so visitors can inspect the whole offering on a regular page. This is a proposed visitor-oriented IA, not a claim that unfamiliar readers have already tested the categories.

[WAI APG disclosure navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) uses semantic navigation, lists, buttons with expanded state, and ordinary links. Tab moves through buttons and revealed links; Enter/Space opens a disclosure; Escape closes it and restores its button. Optional arrows supplement normal tabbing. Its examples are illustrative and require project-specific assistive-technology testing. Use this pattern, retaining normal browser link behavior.

[APG menubar guidance](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/) describes composite widgets with managed focus and arrow navigation; Tab leaves rather than traverses menu items. That extra widget interaction does not fit this reference site's ordinary page links. Do not add `menu`, `menubar`, or `menuitem` roles.

[USWDS header guidance](https://designsystem.digital.gov/components/header/) recommends task-oriented organization, concise labels, visible current sections, and priority ordering. Dropdowns preview lower-level content; click/keyboard activation works across pointer and touch. It recommends testing the implementation and retaining a skip link. Its extended-header guidance supports a separate navigation row when a logo-adjacent row is crowded. Apply the principles, without importing its package or visual system.

[NN/G's original mega-menu guidance](https://www.nngroup.com/articles/mega-menus-work-well/) reports user-testing support for grouped panels that expose options together, differentiates clear/frontloaded labels, and warns about unnecessary controls, touch selection and magnification. This site has relatively shallow groups: restrained one/two-column text panels are enough. Search should remain visible outside panels. Prefer deliberate click opening over timing-dependent hover. No imagery, promotional cards or nested fly-outs are needed.

[WCAG target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) sets a 24-by-24 CSS-pixel minimum or sufficient spacing, with defined exceptions; aim for comfortably padded approximately 44px touch rows here. [WCAG reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) supports testing narrow/zoomed layouts without page-wide horizontal scrolling. These targets inform the checks below; they do not constitute certification.

## Desktop and mobile behavior

- Desktop: retain brand/countdown row and a modest second row for five triggers. Utilities remain visually distinct and visible. One panel open at a time; panel anchored to header and constrained to wrapper. A one/two-column list with three rows fits the larger six-link categories; do not force a full-width mega-menu for the two-link About category. Text and clear borders carry hierarchy. Current category is visibly marked; only its actual destination link gets `aria-current="page"`.
- Open on button activation, not pointer hover or focus alone. Focus remains on the button until Tab enters links. Escape closes current panel and returns focus. Outside pointer activation or focus leaving desktop navigation closes the panel; clicking another trigger switches it. Hidden links are absent from the tab order/accessibility tree. Preserve modified-click/new-tab/link-context behavior.
- Use a content-tested breakpoint around 900px rather than the current blanket 1199px collapse. Test 900/960/1024 widths and choose the actual fit point. If previews make it crowded, remove previews before raising the breakpoint. Prevent overlays covering countdown/results strip improperly.
- Mobile: logo plus Menu button; visible utility row even while closed. Menu reveals category buttons and an **inline expanding region that pushes the page down**, not the existing fixed full-screen sheet. Same category/links/description content, one category expanded at a time, full-width touch rows. Page remains scrollable; no scroll lock, modal semantics or focus trap. Escape and explicit close return focus to Menu when closing the whole mobile region; otherwise category Escape returns category trigger. Explicit link activation closes navigation even on same-route anchors or query-only changes; route/history changes also reset it.
- Mobile focus may move normally into page content. Do not make ordinary Tab movement unexpectedly reopen or trap the menu. On breakpoint change clear incompatible open states and avoid hiding a currently focused element without safe focus handling. Respect reduced motion and forced colors; caret/focus/current marks cannot depend on color alone.

## Directory, centralized manifest and scope

`/resources` should be server-rendered HTML with page title/standfirst, grouped named links and descriptions from the same manifest as header and footer. All groups visible, no disclosure necessary. Start here and Search are clear entry points; packet pages appear in Teach. Article/profile subpages remain accessible through their category indexes and search; a global list of every article/politician/news day would dilute the directory. Print/export routes and embeds stay contextual task actions rather than global destinations. The directory works without JavaScript and gives a durable fallback to collapsed navigation.

Political inventory confirmed all 22 non-home primary pages already appear in the footer, so the gap is header visibility rather than truly orphaned content. Results/Government and article index hubs are missing from the hardcoded search resource corpus; XML sitemap currently omits Home. Include those via the centralized manifest and explicit root route. The 404 page also consumes `NAV`; keep its canonical routes concise. Teaching fragments must resolve to real IDs and must not become fragment URLs in XML sitemap.

Current `lib/site.ts` stores 11 primary links, ten `more` links and separate Teach. `SiteNav` only renders primary links; mobile adds Search/Start, but still omits all `more` resources. `app/layout.tsx` footer includes them. Header styles hide the full link row below 1200px; mobile uses fixed overlay and document overflow lock. Current Escape closes without restoring trigger focus. The expanded overlay has no modal focus containment, which the proposed inline model removes from the design.

Replace the misleading primary/more split with stable group IDs and entries containing href, label and short description. Flattened `NAV` remains derived for existing sitemap/search/home consumers; inspect every consumer before changing the contract. Footer mirrors new groups and utilities; do not duplicate Teach as a sixth unrelated block. `/resources` metadata/search aliases should include resources, tools, directory and site map. Sitemap now uses a canonical-path helper to remove fragment/query duplicates, includes Home and dated briefing pages, and retains packet routes. Preserve canonical routes, exact current-page marking for groups with nested pages, and sourced metadata; descriptions must not promise live results or human-reviewed changes when unavailable.

Authorized implementation ownership: `lib/site.ts`, `components/SiteNav.tsx`, focused header/footer rules in `app/globals.css` or dedicated nav CSS, `app/layout.tsx` utilities/footer, new `app/resources/page.tsx`, `app/sitemap.ts`, search index generation and navigation-focused tests. Preserve unrelated latest palette and content work. No dependencies or new backend. Installed Next server/client and Link guides were inspected: directory stays a Server Component, interactive state stays in SiteNav, and internal destinations use Link.

## Verification and practical risks

1. Manifest coverage: all prior 22 global destinations retained; four Teaching section IDs and new resources directory resolve. No duplicate href entries or wrong packet titles. Search/sitemap/footer derive correct entries and Home remains a working logo link.
2. Keyboard: open each category with Space/Enter, Tab/Shift-Tab through links, Escape returns correct trigger, Tab out closes desktop panel, hidden links never receive focus, click/close/breakpoint transitions leave focus sensible. Same-path navigation closes. Modified link actions remain native.
3. Touch/mouse and layout: 390/320 mobile; 900/960/1024/1280 desktop; landscape; 200%/400% zoom; long contact and packet labels; all panels contained with no page overflow. Inline expansion does not clip or lock the page. Visible utilities remain reachable.
4. Accessibility: nav/list/button/link semantics, expanded/controls/current states, skip link, screen-reader announcements and forced-colors focus/caret; manual NVDA/browser smoke if available. Automated checks support but cannot replace that pass.
5. Findability tasks for a new reader/educator: find all submitted lists, an unknown term, local 2022 turnout, compare issue evidence, a facilitator packet, material changes and the correction contact. Correct grouping is an inference until tested with visitors; no task-time guarantee.
